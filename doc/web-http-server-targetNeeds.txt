🧱 三、完整后台功能模块划分（建议版，你可以根据你的设计进行小范围的修改）
🟢 1. 首页 / 仪表盘
作用：监控整体升级情况
功能：
	•	设备总数
	•	在线设备数
	•	升级成功/失败统计
	•	最近升级任务
	•	实时日志趋势


🟢 2. 设备管理（核心🔥）
对应表：device
功能：
	•	基础功能：针对设备列表的的增删改查。设备列表（按照IMEI），左侧需要做一个设备分组tree结构。因为设备是不直接和用户关联的，而是挂载在一个分组下。设备组和设备的关系是一对多关系
	    展示字段有：设备基础信息相关字段。此外还有：在线状态、固件版本、最后在线时间（从redis查，这个字段你先空着，后续我来实现设备网关相关的功能）


🟢 3. 设备分组（本质上就是一个设备分组信息列表的CRUD操作）
对应表：
device_group
device_group_relation
功能：
    •   基础功能，针对设备组的增删改查。例如：1.创建设备分组（例如：产线一组 / 产线二组）2.修改设备组名称 3.删除设备分组，同时删除分组下关联的设备


🟢 4. 固件包管理（展示固件信息的一个列表。可以有删除固件操作，新增固件）
功能：
	•	上传固件
	•	管理版本
	•	校验包（MD5/CRC）


🟢 5. 升级任务管理（核心🔥你先空着，不用实现。我再仔细设计一下）
对应表：
upgrade_task
batch_upgrade_task
功能：这一块你先空着，不用你来实现。这个由我来实现。
     改模块的核心功能是：就是当设备连接至gateway后，可以在设备列表右侧点击‘开始升级’，然后后端代码创建一条upgradeTask记录 写入upgrade_task表


🟢 6. 升级日志（核心🔥）
对应表：
    device_upgrade_log
功能：
	•	查看每个设备升级过程
	•	状态流转：INIT → PENDING → UPGRADING → SUCCESS / FAIL / TIMEOUT


🟢 7. 用户管理
对应表：
    user
功能：
	•	登录（基于JWT+阿里云短信注册账户。因为我想做成全局唯一的用户，才能确定operate_log是哪个用户在操作，如果是自己创建账号，很可能导致不同的用户共用一个账号，到时候 日志表就不好排查是谁建立的升级任务，是谁点击的‘开始升级’）
	•	用户管理
	•	权限控制（可简单做，你觉得怎么实现比较合理 就按照你的想法来）


🟢 8. 操作日志
对应表：
    operate_log
功能：

	•	谁做了什么
	•	审计用
