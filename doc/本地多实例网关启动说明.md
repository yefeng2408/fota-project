# 本地 IDEA 多实例网关启动说明

本文档用于在本地 IDEA 开发环境启动多个 gateway 实例，验证多实例设备路由表和 OTA 升级链路。

## 1. 启动配置

项目已内置 IDEA 共享 Run Configurations：

```text
.idea/runConfigurations/FOTA_Web_Local.xml
.idea/runConfigurations/FOTA_Gateway_1_Local.xml
.idea/runConfigurations/FOTA_Gateway_2_Local.xml
.idea/runConfigurations/FOTA_Mock_1_Local.xml
.idea/runConfigurations/FOTA_Mock_2_Local.xml
```

如果 IDEA 没有立即显示这些配置，可以执行：

```text
File -> Reload All from Disk
```

或重新打开项目。

## 2. 本地端口规划

| 配置 | HTTP 端口 | TCP 端口 | 说明 |
| --- | --- | --- | --- |
| `FOTA Web Local` | `8080` | - | web 管理服务 |
| `FOTA Gateway-1 Local` | `8081` | `7611` | gateway 实例 1 |
| `FOTA Gateway-2 Local` | `8083` | `7612` | gateway 实例 2 |
| `FOTA Mock-1 Local` | `8082` | 连接 `7611` | 模拟设备服务 1 |
| `FOTA Mock-2 Local` | `8084` | 连接 `7612` | 模拟设备服务 2 |

同一台机器上多个 gateway 进程不能监听同一个 HTTP/TCP 端口，所以本地通过错开端口模拟多实例。

## 3. 启动顺序

先启动基础依赖：

```text
MySQL
Redis
MinIO
RocketMQ NameServer
RocketMQ Broker
```

然后在 IDEA 中按顺序启动：

```text
1. FOTA Web Local
2. FOTA Gateway-1 Local
3. FOTA Gateway-2 Local
4. FOTA Mock-1 Local
5. FOTA Mock-2 Local
```

`FOTA Web Local` 已配置：

```text
-DGATEWAY_ROUTE_FALLBACK_ENABLED=false
-DMOCK_DEVICE_HTTP_URLS=http://127.0.0.1:8082,http://127.0.0.1:8084
```

这表示 web 下发升级指令时必须查询 Redis 设备在线路由，不会回退到固定 `gateway.http.url`，更适合验证多实例行为。

同时，web 调用 `/api/mock-devices/online` 或 `/api/mock-devices/offline` 时，会把设备 IMEI 按 hash 稳定分片到两个 mock-device 服务：

```text
Mock-1: http://127.0.0.1:8082 -> 连接 gateway-1:7611
Mock-2: http://127.0.0.1:8084 -> 连接 gateway-2:7612
```

这样批量模拟 1000 台设备上线时，设备会分散连接到 gateway-1 和 gateway-2，而不是全部连接到 gateway-1。

## 4. Run Configuration 参数

### FOTA Gateway-1 Local

```text
-Dserver.port=8081
-Dnetty.server.port=7611
-DGATEWAY_INSTANCE_ID=gateway-1
-DGATEWAY_INSTANCE_HTTP_URL=http://127.0.0.1:8081
-DGATEWAY_INSTANCE_TCP_HOST=127.0.0.1
```

### FOTA Gateway-2 Local

```text
-Dserver.port=8083
-Dnetty.server.port=7612
-DGATEWAY_INSTANCE_ID=gateway-2
-DGATEWAY_INSTANCE_HTTP_URL=http://127.0.0.1:8083
-DGATEWAY_INSTANCE_TCP_HOST=127.0.0.1
```

### FOTA Mock-1 Local

```text
-Dserver.port=8082
-Dnetty.device-gateway-server.host=127.0.0.1
-Dnetty.device-gateway-server.port=7611
```

### FOTA Mock-2 Local

```text
-Dserver.port=8084
-Dnetty.device-gateway-server.host=127.0.0.1
-Dnetty.device-gateway-server.port=7612
```

## 5. Redis 验证命令

查看 gateway 实例注册：

```bash
redis-cli keys 'fota:gateway:instance:*'
redis-cli hgetall 'fota:gateway:instance:gateway-1'
redis-cli hgetall 'fota:gateway:instance:gateway-2'
```

查看设备在线路由：

```bash
redis-cli keys 'fota:device:online:*'
redis-cli hgetall 'fota:device:online:你的IMEI'
```

设备在线路由中应包含：

```text
instanceId
sessionId
channelId
lastSeenAt
```

如果设备连接的是 `FOTA Gateway-1 Local`，则 `instanceId=gateway-1`。

如果设备连接的是 `FOTA Gateway-2 Local`，则 `instanceId=gateway-2`。

## 6. 验收方式

### 6.1 验证 gateway 实例心跳

两个 gateway 启动后，Redis 中应存在：

```text
fota:gateway:instance:gateway-1
fota:gateway:instance:gateway-2
```

并且 `lastHeartbeatAt` 会持续变化。

### 6.2 验证设备路由

启动 mock-device 后，通过平台让设备上线。

如果设备由 `Mock-1` 模拟上线，应连接到 gateway-1：

```text
fota:device:online:{imei}.instanceId = gateway-1
```

如果设备由 `Mock-2` 模拟上线，应连接到 gateway-2：

```text
fota:device:online:{imei}.instanceId = gateway-2
```

### 6.3 验证升级指令路由

对连接到 gateway-2 的设备发起升级时，web 应读取：

```text
fota:device:online:{imei}.instanceId = gateway-2
```

然后调用：

```text
http://127.0.0.1:8083/internal/device/upgrade-request
```

而不是固定调用 gateway-1。

## 7. 常见问题

### 7.1 第二个 gateway 启动失败，提示端口占用

检查 `server.port` 和 `netty.server.port` 是否与其它实例重复。

本地多实例必须错开：

```text
gateway-1: 8081 / 7611
gateway-2: 8083 / 7612
```

### 7.2 web 下发升级提示设备不在线

检查：

```bash
redis-cli hgetall 'fota:device:online:你的IMEI'
```

如果不存在，说明 mock-device 尚未上线或 gateway 没有收到 `DeviceBootUp`。

### 7.3 web 找不到 gateway 实例

检查：

```bash
redis-cli hgetall 'fota:gateway:instance:gateway-1'
redis-cli hgetall 'fota:gateway:instance:gateway-2'
```

如果 key 不存在，说明 gateway 心跳没有注册成功，或 Redis 配置不一致。

### 7.4 想临时兼容单 gateway

可以把 web 的参数改成：

```text
-DGATEWAY_ROUTE_FALLBACK_ENABLED=true
```

这样找不到设备路由时会回退到 `gateway.http.url`。

多实例验证时不建议开启 fallback。
